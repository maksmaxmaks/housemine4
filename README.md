# Лаунчер ХаусМайн 4

Свой лаунчер Minecraft для сборки и сервера **ХаусМайн 4**: тёмно-фиолетовый интерфейс по вашим референсам, вход по нику (оффлайн) или через лицензионный аккаунт Microsoft, новости, 3D-скин игрока («buddy»), кнопка «Начать игру» и удалённое обновление сборки с уведомлением игрокам.

Игрок скачивает один `.exe`. Всё остальное (Java, Minecraft, загрузчик модов, ваша сборка) лаунчер ставит и обновляет сам.

---

## 1. Как это устроено

```
  Вы                                   Хостинг (любой сайт)                Игрок
  ───                                  ────────────────────                ─────
  publish/modpack  ──npm run pack──▶   manifest.json  ◀────────────────── лаунчер раз в 5 минут
  publish/news.json                    news.json                           смотрит, что нового,
                                       files/… (ваши моды и конфиги)        качает только изменённое
```

* **Лаунчер** (`.exe`) собирается один раз и почти не меняется.
* **Сборка и новости** лежат на вашем хостинге. Чтобы выпустить обновление, вы меняете файлы и снова выкладываете папку `site` — лаунчер у игроков сам это заметит.

## 2. Первый запуск проекта

### 2.1. Впишите адрес обновлений
Откройте `launcher.config.json` и замените `baseUrl` на адрес папки на вашем хостинге (с `/` на конце), где будет лежать `manifest.json`:

```json
"baseUrl": "https://username.github.io/hausmine4/"
```

Там же можно поправить название сервера, адрес, ссылки на сайт/Discord, память по умолчанию.
Фон и логотип «Хаусмайн 4» — это картинка `src/renderer/assets/hero.jpg`; чтобы сменить, замените файл (1672×941).

### 2.2. Получите `.exe`

**Вариант А — без установки программ (рекомендую).** Залейте папку проекта в репозиторий GitHub и откройте *Actions → «Сборка лаунчера» → Run workflow*. Через несколько минут внизу страницы появится архив `HausMine4-windows` с установщиком (`HausMine 4 Setup.exe`) и портативной версией (`HausMine4-portable.exe`). Если создать тег `v1.0.0`, файлы автоматически попадут в Releases.

**Вариант Б — на своём компьютере.** Нужен [Node.js 22+](https://nodejs.org):
```
npm install
npm start          # запустить для проверки
npm run dist       # собрать .exe в папку dist
```

> Windows может показать предупреждение SmartScreen («неизвестный издатель»): `.exe` не подписан сертификатом. Для небольшого сервера это нормально — нажмите «Подробнее → Выполнить в любом случае». Подпись кода покупается отдельно.

## 3. Куда выложить сборку (хостинг)

Подойдёт любой, откуда файлы отдаются по обычной ссылке:

* **GitHub Pages** — бесплатно: создайте репозиторий, включите Pages, выкладывайте содержимое `publish/site`. Ограничения: файл до 100 МБ, весь сайт до 1 ГБ.
* Свой сервер/VPS с nginx, Яндекс Object Storage, любой статический хостинг.
* Если сборка тяжёлая, большие файлы можно держать отдельно (например, в GitHub Releases) — укажите их адрес в `pack.config.json` → `"fileBaseUrl": "https://…/"`. Манифест и новости при этом остаются на лёгком хостинге.

## 4. Как загрузить и обновлять сборку

1. Положите файлы сборки в **`publish/modpack/`** — так же, как они лежат в `.minecraft` вашей рабочей сборки: `mods/`, `config/`, `resourcepacks/`, `shaderpacks/`, `options.txt` и т. д. (Миры `saves`, логи и скриншоты игнорируются сами.)
2. Откройте **`publish/pack.config.json`** и укажите:
   * `minecraft` — версия игры, например `"1.20.1"`;
   * `loader` — загрузчик: `{"type": "fabric", "version": "latest"}`. Поддерживаются `fabric`, `quilt`, `forge`, `neoforge`, `vanilla`. Для Forge/NeoForge версию укажите точно (например `"47.2.0"`);
   * `server` — адрес вашего сервера (лаунчер сам зайдёт на него после запуска);
   * `changelog` — что нового (покажется игрокам);
   * `required: true` — обязательное обновление.
3. Выполните:
   ```
   npm run pack
   ```
   Появится папка **`publish/site`** — манифест, ваши файлы и новости.
4. Загрузите **содержимое `publish/site`** на хостинг (по адресу `baseUrl`).

**Чтобы выпустить обновление** — замените/добавьте/удалите файлы в `modpack`, снова `npm run pack` (версия повысится сама, `1.0.0 → 1.0.1`) и снова загрузите `site`. Игроки получат уведомление и обновятся кнопкой; докачивается только изменённое, удалённые вами файлы удаляются, а **личные файлы игроков** (миры, свои моды, настройки) не трогаются.

Полезные параметры: `npm run pack -- --bump minor` (повысить вручную), `--version 2.0.0`, `--keep-version`.

**Особые файлы** (в `pack.config.json`):
* `optional` — моды, которые игрок может отключить в окне «Моды» (по маскам, например `"mods/*sodium*"`);
* `once` — кладутся только при первой установке и дальше не перезаписываются (`options.txt`, `servers.dat`);
* `ignore` — что не публиковать.

### Уведомления об обновлении
* Лаунчер проверяет обновления при запуске и каждые 5 минут; игрок видит красную плашку «Доступно обновление сборки» с кнопками «Что нового» и «Обновить», а кнопка «Играть» превращается в «Обновить и играть».
* Пока лаунчер в трее (включено по умолчанию: закрытие окна сворачивает его), приходит **системное уведомление Windows**. Полностью закрытый лаунчер, как у любой программы, уведомлять не может — тогда игрок увидит обновление при следующем запуске.
* Срочное сообщение всем (технические работы и т. п.): впишите `announcement` в `pack.config.json` (`id` меняйте для нового сообщения) — оно появится плашкой сверху.
* Новая версия самого лаунчера: `launcher: {"version": "1.1.0", "url": "ссылка на скачивание"}` — игроки увидят плашку со ссылкой.

## 5. Новости

Файл **`publish/news.json`** (его же выкладывает `npm run pack`). Новость — это заголовок, текст, дата и необязательные `tag`, `image` (ссылка на картинку), `url` (кнопка «Подробнее»). В тексте работает `**жирный**` и ссылки. Добавить новость командой:

```
npm run news -- add "Ивент на выходных" "В субботу в 18:00 охота на дракона!" --tag Событие
npm run news -- list
npm run news -- remove <id>
```
Затем загрузите обновлённый `news.json` на хостинг — лента у игроков обновится сама (при следующей проверке), без переустановки. Непрочитанные новости помечаются красной точкой.

## 6. Вход в аккаунт

* **Оффлайн** — игрок вводит ник (латиница, цифры, `_`, 3–16 символов).
* **Лицензия Microsoft** — вход через окно Microsoft; пароль лаунчер не видит. Токены хранятся зашифрованными средствами Windows.

> **Важно про сервер.** Чтобы на сервер могли зайти и оффлайн-, и лицензионные игроки, в `server.properties` должно быть `online-mode=false`. Это даёт возможность подделывать чужой ник, поэтому для такого сервера обычно ставят плагин авторизации (например AuthMe) и/или SkinsRestorer.
>
> **Про вход Microsoft.** По умолчанию используется идентификатор приложения официального лаунчера Minecraft (`msClientId`) — так делают многие сторонние лаунчеры, но это «серая зона». Если захотите «по правилам», зарегистрируйте своё приложение в Azure и запросите доступ к Minecraft API у Mojang, затем впишите его идентификатор в `msClientId` (redirect URI: `https://login.live.com/oauth20_desktop.srf`).

## 7. Скин («buddy»)

В левой панели — трёхмерная модель с вашим скином: тянуть мышкой — вращать, клик — помахать, голова следит за курсором. Откуда берётся скин (по порядку):

1. **Скин с вашего сервера** — адрес-шаблон в `pack.config.json` → `skins.template`, например `"https://skins.example.com/{name}.png"` (поддерживаются `{name}` и `{uuid}`). Подойдёт любая система скинов, отдающая PNG по нику;
2. скин лицензионного аккаунта;
3. запасной вариант `skins.fallback`: `"mojang"` (по нику), `"ely"` (Ely.by) или `"none"`;
4. стандартный скин.

Чтобы скин видели **в самой игре** на оффлайн-сервере, нужна система скинов на сервере (SkinsRestorer и т. п.) или клиентский мод вроде CustomSkinLoader в сборке — лаунчер только показывает скин в своём окне.

## 8. Проверка у себя до выкладки

```
npm run pack
npm run serve                      # раздаёт publish/site на http://localhost:8080/
```
В другом окне (Windows PowerShell): `$env:HM_BASE_URL="http://localhost:8080/"; npm start`

Все данные лаунчера лежат в `%APPDATA%\.hausmine4` (игра — в подпапке `instance`). Журнал — значок монитора в лаунчере.

## 9. Что проверено, а что нет

Автотесты (`npm test`, 16 штук) прогоняют на имитации серверов Mojang/Fabric/Adoptium/Microsoft: установку Java, Minecraft и Fabric, сборку аргументов запуска, публикацию и обновление сборки (докачка, удаление, сохранность файлов игрока, опциональные моды, ремонт), работу без связи, цепочку входа Microsoft, пинг сервера, скины, IPC-команды. Интерфейс просмотрен в браузере (включая 3D-модель).

**Не проверялось на реальных сервисах** (в среде разработки не было доступа к интернету и Electron): настоящая загрузка с серверов Mojang/Fabric/Adoptium, вход в живой аккаунт Microsoft, установщики Forge/NeoForge, сам запуск `.exe` на Windows. Поэтому первый пробный запуск лучше сделать самому: оффлайн-ник → «Установить и играть» → загляните в журнал, если что-то пойдёт не так.
Шрифт Pixelify Sans подтягивается автоматически при `npm install`; до этого интерфейс использует запасной моноширинный шрифт.

## 10. Структура проекта

```
launcher.config.json      настройки лаунчера (адрес обновлений и т. д.)
publish/                  то, что вы публикуете (modpack, pack.config.json, news.json)
tools/                    pack.js (публикация), news.js, serve.js
src/main/                 ядро: вход, Java, Minecraft, загрузчики, синхронизация, запуск
src/renderer/             интерфейс (index.html, styles.css, app.js, buddy.js, assets)
test/                     автотесты
.github/workflows/        автоматическая сборка .exe
```
